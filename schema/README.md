# schema/

Generated by `cargo xtask gen`; never edit by hand. `cargo xtask gen --check` (part of `just check`) fails with a unified diff when a committed file is stale, and the insta snapshot of `commands.json` in `xtask` makes a catalog change need `cargo insta review`.

| File | Content |
|---|---|
| `commands.json` | document and engine commands: flags, MCP exposure, annotations, input/output JSON Schema, `error_codes` |
| `queries.json` | queries, same shape |
| `events.json` | events the engine broadcasts |
| `mcp-tools.json` | core MCP tools; tool name = command name with `.` replaced by `_` |
| `patch-fixtures.json` | patches produced by real commands on a seeded-ID document, for the TS patch applier |
| `schema-hash.txt` | sha256 of `commands.json`; also `crates/cutweave-commands/src/schema_hash.rs` (`SCHEMA_HASH`) |

The human-readable table is `docs/reference/commands.md`.

One file here is **hand-maintained**, not generated: `parity-exempt.toml`, the registry entries the CLI = MCP = RPC parity test (`crates/cutweave-api/tests/parity`, WP-1O.02) allows to be unreachable over MCP (`mcp = "hidden"`), each with its reason. Changes to it are reviewed by CODEOWNERS.
