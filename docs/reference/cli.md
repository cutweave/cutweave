# `cutweave` command line

> Generated by `cargo xtask gen` from `cutweave-cli`; do not edit by hand.

One binary (ADR-0002): `cutweave engine` is the engine process the desktop app starts, and the other subcommands drive an engine from scripts, terminals and agents. Architecture: [§6](../01-architecture.md#6-api-surfaces-cutweave-api); the launch flags are specified in [launch-protocol.md](launch-protocol.md), the wire protocol the CLI attaches with in [rpc.md](rpc.md), the commands in [commands.md](commands.md).

## Attach or spawn

`exec` and `query` need an engine:

- **Attach (default).** The CLI reads the run-files in `--run-dir` (default `~/.cutweave/run`), picks the one engine that is running (`--pid` chooses among several), connects to `ws://127.0.0.1:<port>/rpc` with the run-file's `cli` agent token and sends JSON-RPC calls, each with a fresh `_meta.request_id`. Edits are visible to everyone else attached (the desktop UI included) and land in the engine's history as the actor `agent:cli`.
- **Spawn.** With `--headless`, `--project`, `--deterministic-ids`, `--allow-root` or `--dev-stub-media` the CLI starts a one-shot engine inside the process (no server, no run-file), runs the request and shuts it down. Nothing is saved unless the request saves (`--save`, or the `project.save` command): unsaved work stays in the journal, as for any engine. A project another process holds is `project_locked`.

Agents and the CLI are confined to the folders of `--allow-root` plus the project folder (launch-protocol.md, "Path policy").

## Input and output

`exec` takes one step, `{"cmd": "clip.split", "args": {...}}`, or an array of steps (or `{"steps": [...]}`) that runs as **one transaction and one undo step**: all steps apply or none does, and a failing step is reported as `failed_step`. Engine commands (`edit.undo`, `project.open`, `media.import`, `job.*`, `view.*`) cannot join a transaction; run one as the only step.

Results are one JSON object on stdout: `{"rev", "committed_rev", "output"}` for one step, `{"rev", "committed_rev", "steps": [{"cmd", "output"}]}` for a batch. Errors are one JSON object on stderr in the engine's wire form (`{"code": "not_found", "message": ..., ...}`).

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | The command, query or export failed (the error JSON has the engine's machine `code`) |
| 2 | Usage: bad arguments or input |
| 3 | No engine to attach to, several running without `--pid`, or the connection was lost |
| 64 | Reserved subcommand not built yet (`worker`; `mcp` until stdio MCP lands) |

For `cutweave engine` the exit codes are the launch protocol's (0, 1, 2, 10-13).

## `cutweave`

```text
Cutweave: open-source video editor engine and command line.

`exec` and `query` talk to an engine: they attach to a running one (found through its run-file) or, with --headless or --project, start a one-shot engine inside the process. Results are JSON on stdout; errors are JSON on stderr. Exit codes: 0 ok, 1 command error, 2 usage, 3 no engine, 64 not implemented in this build.

Usage: cutweave [COMMAND]

Commands:
  engine    Run the engine process (the launch protocol Electron main and scripts speak)
  exec      Run a command, or several as one transaction, and print the result
  query     Run a query and print the result
  commands  List the registered commands and queries
  describe  Print one command's description and JSON Schemas
  render    Export a sequence to a media file (needs the media backend; not available yet)
  mcp       Serve MCP over stdio (arrives with WP-1J.03)
  worker    Reserved: the sandboxed worker process
  help      Print this message or the help of the given subcommand(s)

Options:
  -V, --version
          Print the cutweave version, the engine version and the command schema hash

  -h, --help
          Print help (see a summary with '-h')
```

### `cutweave engine`

```text
Run the engine process (the launch protocol Electron main and scripts speak)

Usage: cutweave engine [OPTIONS]

Options:
      --headless
          No UI credential: agents and the CLI use the run-file's agent tokens. Without it the engine runs in GUI mode and reads its UI credential from stdin

      --port <PORT>
          Bind 127.0.0.1:PORT; 0 picks a free port

      --token-stdin
          Accepted for compatibility: a GUI engine always reads its UI credential from stdin

      --project <PATH>
          Open this project folder or `.cutweave` file at start

      --run-dir <DIR>
          Run-file directory (default `~/.cutweave/run`)

      --allow-origin <ORIGIN>
          An extra allowed `Origin` (repeatable)

      --allow-root <DIR>
          A folder agents may import from or save into (repeatable)

      --deterministic-ids <SEED>
          Seeded ids and a frozen clock (tests). `CUTWEAVE_DETERMINISTIC_IDS` does the same

      --i-know-this-is-a-test
          Lets a GUI engine run with deterministic ids

      --log-dir <DIR>
          Log directory (default `~/.cutweave/logs`)

      --no-log
          No log file

      --handshake-timeout-ms <MS>
          How long a GUI engine waits for the handshake line (default 5000)

      --dev-stub-media
          Dev only: fake media probing until the FFmpeg backend lands. `CUTWEAVE_DEV_STUB_MEDIA=1` does the same

  -h, --help
          Print help
```

### `cutweave exec`

```text
Run a command, or several as one transaction, and print the result

Usage: cutweave exec [OPTIONS] [JSON]

Arguments:
  [JSON]
          The request as JSON, or `-` for stdin. One step `{"cmd": "clip.split", "args": {...}}`, or an array of steps (or `{"steps": [...]}`) that runs as one transaction and one undo step

Options:
  -f, --file <PATH>
          Read the request from this file (`-` for stdin)

      --expected-rev <REV>
          Fail with `conflict` unless the document is at this revision

      --save
          After a successful run, save the project (`project.save`). A one-shot engine otherwise leaves its changes in the journal only

  -h, --help
          Print help

Engine selection:
      --headless
          Start a one-shot engine in this process instead of attaching to a running one

      --project <PATH>
          Open this project folder or `.cutweave` file in the spawned engine (implies --headless)

      --pid <PID>
          Attach to the engine with this process id when several are running

      --run-dir <DIR>
          Directory holding the engines' run-files (default `~/.cutweave/run`)

Spawned engine:
      --deterministic-ids <SEED>
          Seed the spawned engine's ids and freeze its clock, so identical scripts give identical output (implies --headless). `CUTWEAVE_DETERMINISTIC_IDS` does the same

      --allow-root <DIR>
          A folder the spawned engine lets this command import from or save into (repeatable; implies --headless). The project folder is always allowed

      --dev-stub-media
          Dev only: fake media probing in the spawned engine (implies --headless). `CUTWEAVE_DEV_STUB_MEDIA=1` does the same
```
