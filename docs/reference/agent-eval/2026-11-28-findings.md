# What the first agent evaluation says (2026-11-28, claude-sonnet-5-5)

A reading of [the generated report](2026-11-28-claude-sonnet-5-5.md) for the decisions it was run for ([ADR-0040](../../adr/0040-mcp-at-scale.md) question 4, [ADR-0041](../../adr/0041-expected-rev-in-the-listed-tool-schemas.md), [ADR-0044](../../adr/0044-listing-render-contact-sheet.md)). How the evaluation works: [agent-eval.md](../agent-eval.md).

## What this run can and cannot show

- One run of one model: 57 sessions, ten tasks, each variant once. A difference of a call or a few percent is within what a second run would change.
- Every session passed. The tasks are short and the model is strong, so success rate cannot tell the variants apart here. The differences are in cost and in how often a first call was valid.
- The engine had stub media and no renderer, so nothing visual was exercised, and no task had two clients editing at once. The run says nothing direct about `render_contact_sheet` or `expected_rev`.
- The whole run used about 4.5 million input tokens (about three quarters of them read from the prompt cache) and about 30,000 output tokens.

## Findings

| Question | Result |
|---|---|
| Do parameter descriptions help a client that loads every definition? | First calls valid: 37 of 39 without them, 37 of 37 with them. They cost 46% more input tokens per session (79,500 to 116,300). |
| Do they help a client that defers definitions? | No difference seen: 45 of 48 and 48 of 51 first calls valid, and the same tokens within noise. |
| What does deferring definitions save? | 41% of input tokens on the standard list (79,500 to 46,600 per session) and 62% on the described one, for a third of a turn to most of a turn more. |
| What does a core tool save over `cutweave_execute`? | 26% of input tokens, 29% of tool calls and most of a turn. Every task still passed without its core tools. |
| What does a batch save? | About half a turn and 6% of tokens on four tasks; too few to lean on. |

Two things the transcripts show that the table does not:

- **With deferred definitions the model rarely searched for a core tool** (0.1 tool searches per session). It used the tools that are always loaded: `timeline_get`, then `cutweave_search_commands`, `cutweave_describe_command` and `cutweave_execute`. So for these clients the catalog route is the main route, and the always-load marks decide it.
- **Wrong guesses at names**: `clip.speed` for `clip.set_speed` (three sessions asked `cutweave_describe_command` and got `not_found`), and core tool names called when they were not listed. A `not_found` that names the closest commands would save those turns.

## What it means for the open decisions

- **Parameter descriptions stay off the standard list** (ADR-0039, ADR-0040 question 4): supported. They buy two valid first calls in 39 for 46% more tokens, and both lists passed every task.
- **The described profile**: no benefit shown for clients that defer definitions, and no harm. It is expensive for a client that loads everything. A copied setup should only point at it when the client really defers definitions.
- **The standard budget (ADR-0041, ADR-0044)**: this run did not exercise either candidate. What it does show is that a tool the model actually uses is worth far more as a listed tool than its listing costs (26% of a session's tokens against a few hundred tokens of list), and that the list is paid on every turn by clients that load it. Raising the budget by 500 tokens would add about 7% to the definitions those clients carry. The case for listing `expected_rev` and the contact sheet therefore rests on how often agents use them, which needs a task with two editors and an engine with a renderer.

## Follow-ups this suggests

1. A `not_found` answer from `cutweave_describe_command` and `cutweave_execute` that suggests the nearest command names.
2. Evaluation tasks for concurrency (`expected_rev`) and for looking at the picture (on an engine with a renderer), so the two budget questions can be measured.
3. A second run, and a run on a smaller model, before reading small differences as real.
